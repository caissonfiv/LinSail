# 托管模型与后续商业化

## 当前已实现

客户端可同时保存 `byok` 和 `hosted` 配置。两者都使用配置的 Base URL、模型 ID 和独立用户 Key，运行时 `/use 名称` 切换。HTTP 401 / 402 / 403 / 429 有清晰提示。

**当前没有运行中的官方网关、购买功能、余额系统或支付处理。** `hosted` 是可用的连接配置类型，不代表后端已建成。服务地址没有写死，可以在运营方服务就绪后配置，无需更改终端执行模块。

## 运营方接入契约

网关提供 HTTPS `POST /v1/chat/completions`，支持非流式请求、工具调用以及标准的 assistant/tool 消息。接受 LinSail 用户自己的短权限服务令牌；运营方的上游服务 Key 永远留在服务器。

```text
LinSail 客户端
    │ 用户服务令牌
    ▼
你的 HTTPS 网关
    ├── 账户认证 / 模型许可 / 额度检查
    ├── 请求 ID / 幂等账务 / 用量记录
    └── 模型供应商（服务端密钥）
```

客户端不会主动上传配置密钥以外的凭证，也不应承担可信计费逻辑。拒绝请求时，网关返回相应 HTTP 状态；工具调用必须原样保留结构。

## 下一阶段建议实现顺序

1. 在你的域名和主机上提供模型网关：用户令牌、限流、成本上限和用量查询。
2. 提供账户和余额页面，服务条款和隐私说明；先以测试额度验证账务。
3. 确定实际收款主体、支付服务商、币种、价格及退款流程后接入支付。
4. 通过经验证签名的支付 webhook 记账，使用交易 ID 去重，不信任客户端“支付成功”通知。
5. 为 CLI 增加登录与购买网页入口；保留 BYOK 路径。

这份路线不包含虚构的购买链接或假余额。模型供应商费用、主机费用、域名和收款账号都需要运营方实际提供。
